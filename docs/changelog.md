# 仕様変更履歴

本書には、計算結果、データ構造、運用へ影響する重要な仕様変更を記録する。細かな文言修正はGit履歴だけで管理してよい。

## 2026-09-03

### 初期所属と急な欠勤・交代対応

- スタッフ登録時に、初期所属店舗と所属開始日を必須入力して同時登録するようにした。
- 病気等の急な欠勤を予定休と区別するため、シフト種別に`absence`（急な休み）を追加した。
- 日別シフトで、対象日にいずれかの有効店舗へ所属するシフト未登録スタッフを、他店所属者も含めて交代・応援要員として追加できるようにした。
- 急休者と交代者は別行で保持し、交代者には実際の勤務店舗を登録する方針とした。

### シフトのヘルプ勤務店舗

- シフト作成時に、表示中の自店だけでなく他の有効店舗をヘルプ先として選択できるようにした。ヘルプ先への所属登録は不要とする。
- 勤務店舗候補は店舗マスタから動的に生成し、店舗追加後も自動で選択肢へ反映するようにした。
- 無効店舗と対象日の店休日は新規の勤務店舗候補から除外し、サーバー側でも保存を拒否するようにした。
- ヘルプ勤務シフトがある場合は、ヘルプ先への所属登録がなくても同店舗で勤怠を登録できるようにした。
- シフトのない急な出勤も、対象日にいずれかの有効店舗へ所属していれば、自店・他店を問わず登録できるようにした。

### Phase 3 勤怠・時間計算

- `attendance_records`と日次勤怠画面を追加し、店舗・営業日単位で一括登録できるようにした。
- 日次勤怠から勤務予定者を急な休みへ変更できるようにし、急休行の表示、入力無効化、勤怠実績との競合拒否を追加した。
- 日次勤怠の急休行から、他店所属者を含む代替スタッフと勤務開始を選び、表示中店舗の勤務予定として追加できるようにした。
- 15分単位、日跨ぎ表示、翌10:00上限、実働分数、`work_date`基準の深夜重複時間を共通Serviceで計算するようにした。
- シフトとの差異警告、急な出勤、店休日の確認、同一営業日の店舗競合、確認付き削除を実装した。
- 勤怠時刻は17:00から翌朝10:00までを一続きに並べ、日付を跨いだ後も「翌」を付けず「0:00」等と表示するようにした。
- 9月4日の01:00シフトと実日時9月5日01:00は、どちらも表示上「1:00」、内部では翌日側として扱うようにした。
- 勤怠や給与入力マスタの変更時に、計算済み給与へ再計算必要フラグを設定する基盤を追加した。
- 社員の店舗別・全店舗月間勤務時間を集計する基礎Serviceを追加した。社員給与は計算しない。
- ダッシュボードの勤怠未入力人数と日次勤怠への導線を実データへ接続した。
- MySQLのCHECK制約で、Laravelを経由しない不正な勤怠日時も拒否するようにした。

### Phase 1・2完了監査の反映

- 既存シフトがある日の店休日登録と、既存シフトを在籍・所属期間外にするマスタ変更を拒否することにした。
- 無効店舗は新規の所属・交通費候補から除外し、既存履歴の参照・更新だけ許可することにした。
- 時給・所得税履歴があるアルバイトの社員変更を拒否することにした。
- シフト種別と`store_id`・`start_time`の組み合わせをMySQL CHECK制約でも保証することにした。
- CSV／XLSXによるスタッフ初期移行とExcelテンプレートをPhase 1へ追加した。
- 初期移行はUTF-8／CP932のカンマ区切りCSVに対応し、空行があっても元ファイル上の行番号をエラー表示することにした。

### リポジトリ内文書を正本化

- 元の実装仕様書v3.0と追加確認事項を`docs/`へ統合した。
- 要件、計算、データモデル、ロードマップ、テスト、ADRを分離した。
- 添付資料や会話を読まなくても実装を開始できる構成にした。

### ローカル開発環境

- Docker Composeをローカル開発・動作確認の標準環境とした。
- Migration、Seeder、テスト、ビルド、ファイル生成をDocker上で確認することを完了条件へ追加した。

### 給与支給日と所得税年度

- 給与支給日を対象月の翌月10日に確定した。
- `payrolls.payment_date`を追加した。
- 税額表年度を勤務月ではなく支給日の年で決定することにした。
- 2026年12月勤務分には2027年分税額表が必要となることを明記した。

### 所得税設定履歴

- スタッフの現在値としていた甲欄/乙欄・扶養人数を、適用期間付き`staff_income_tax_settings`へ変更した。
- 給与支給日に有効な設定を使用することにした。

### 交通費

- 店舗別交通費へ`tax_type`を追加した。
- `taxable`と`non_taxable`を管理者が設定することにした。
- 給与結果を合計・課税・非課税の3項目へ分離した。

### 単価履歴

- 時給、店舗別交通費、深夜加算額を適用期間付き履歴へ変更した。
- 勤務日の`work_date`に有効な単価を使用することにした。
- 過去給与へ現在単価を適用しないことにした。

### 給与端数

- 正式給与をスタッフ×月の結果とした。
- 日別整数を合算せず、丸め前精度を保持して各表示単位の最後に切り上げることにした。
- 日別・店舗別表示と正式給与の端数差を許容することにした。

### 在籍・店舗所属

- `employment_status`を廃止した。
- `hired_at`と`retired_at`から在籍状態を導出することにした。
- 店舗所属を適用期間付き履歴へ変更した。

### 全店舗共通の休

- 「休」を店舗状態ではなくスタッフ×営業日の全店舗共通状態とした。
- 1スタッフ×1営業日を、1店舗勤務または休みのどちらか一方に限定した。
- 論理モデルでは`shifts.store_id = NULL`の`off`として一意に保存する方針にした。

### 店休日の勤務

- 店休日の通常シフト禁止を維持した。
- 確認ダイアログ後の勤怠登録を可能にした。
- 店休日勤務も勤怠・交通費・人件費・給与へ含めることにした。

### 深夜加算

- 深夜区間を`work_date 22:00`から翌日8:00までに確定した。
- 翌朝部分も全て元の`work_date`へ帰属させることにした。
- 実時刻だけによる深夜判定を禁止した。
- 実日時が2026-09-05 01:00〜05:00の勤務は、2026-09-04営業日の勤務として扱うことを明記した。

### 勤怠削除と再計算

- 確認後の勤怠削除を可能にした。
- 給与計算入力の変更後、対象給与を「再計算が必要」とすることにした。

### 給与明細

- 提供された給与明細PDFをレイアウト基準に確定した。
- 独自デザインを作成しないことを明記した。
